## Context

当前笔记应用的富文本编辑器（`RichTextEditor`）工具栏左侧有：段落菜单、格式菜单、粘贴图片、选择图片按钮。用户在浏览网页时想保存正文内容到笔记，只能手动复制粘贴，格式丢失严重。项目使用 `flutter_quill` 作为编辑器引擎，内容存储为 Quill Delta JSON 格式。目前无任何 HTTP 请求或 HTML 解析依赖。

## Goals / Non-Goals

**Goals:**
- 在工具栏左侧最右位置添加链接剪藏图标按钮
- 弹窗接收用户输入的 URL
- 通过第三方网页正文提取 API 抓取目标页面正文
- 将提取的 HTML 内容转换为 Quill Delta 并插入编辑器光标位置
- 支持 Windows、Android、Web 三个平台

**Non-Goals:**
- 不自建后端爬虫服务（使用第三方 API）
- 不做本地 HTML 解析（正文提取交给 API）
- 不支持视频/音频内容剪藏
- 不做剪藏历史记录管理
- 不做离线剪藏队列

## Decisions

### 1. 网页正文提取方案：使用第三方 API

**选择**: 调用第三方网页正文提取 API（如 `r.jina.ai`）获取网页 Markdown 正文。

**理由**: 自建爬虫需要维护 User-Agent、反爬策略、各平台适配，成本过高。第三方 API 已处理好这些细节，且返回干净的 Markdown 格式，便于转换为 Quill Delta。

**备选方案**:
- 本地 `html` 包解析：需为每个平台写提取规则，维护成本高
- 自建后端服务：需要服务器资源，超出单机应用范围

### 2. HTTP 客户端：使用 `http` 包

**选择**: `http` 包（纯 Dart HTTP 客户端）。

**理由**: 项目仅需要一个 GET 请求来调用 API，`http` 包足够轻量且全平台兼容。`dio` 功能过多且引入不必要的复杂度。

### 3. 内容转换流程：HTML → Markdown → Quill Delta

**选择**: API 返回 Markdown → 自行转换为 Quill Delta 操作列表 → 插入编辑器。

**理由**:
- API 直接返回 Markdown，格式干净
- Markdown → Quill Delta 转换逻辑简单：标题行加 header 属性，列表加 list 属性，段落直接插入
- 避免引入复杂的 HTML 解析依赖

### 4. UI 交互：Dialog 弹窗 + Loading 状态

**选择**: 点击图标弹出 `AlertDialog`，包含 URL 输入框和确认按钮，请求期间显示 Loading 指示器。

**理由**: 与应用现有交互模式一致，简单直接。

### 5. 插入位置：当前光标处

**选择**: 内容插入到当前光标位置，自动添加来源链接作为底部引用。

**理由**: 用户可以精确控制内容插入位置，来源链接方便日后追溯。

## Risks / Trade-offs

- **[第三方 API 可用性]** → Jina Reader API 有免费额度限制，大量使用可能被限流。缓解：选择有稳定免费额度的 API，后续可切换。
- **[平台网络差异]** → Web 平台存在 CORS 限制。缓解：使用支持 CORS 的 API 端点，或通过代理请求。
- **[正文提取质量]** → 部分网站（如小红书需要登录）可能无法提取完整内容。缓解：在 UI 中展示提取失败的友好提示，建议用户手动复制。
- **[转换格式丢失]** → 复杂排版（表格、嵌套列表）可能无法完美转换。缓解：优先保证标题、段落、粗体、链接等基础格式正确。
