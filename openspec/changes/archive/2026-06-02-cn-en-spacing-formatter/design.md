## Context

当前富文本编辑器使用 Flutter Quill，文档以 Delta 格式存储。工具栏已有段落菜单、格式菜单、图片按钮和 Markdown 开关。需要新增中英文混排空格格式化功能。

## Goals / Non-Goals

**Goals:**
- 在工具栏右侧（Markdown 开关旁）新增格式化按钮
- 对 Quill Document Delta 中的文本节点执行中英文混排空格格式化
- 跳过行内代码（inlineCode）、代码块（codeBlock）、链接/图片（embed）中的内容

**Non-Goals:**
- 不处理 Markdown 文件（仅处理富文本编辑器内容）
- 不提供实时自动格式化（仅手动触发）
- 不修改存储层

## Decisions

### 1. 直接操作 Delta 而非纯文本
**选择**: 遍历 Document 的节点树，对每个纯文本 Leaf 节点执行格式化。
**理由**: 操作 Delta 可以保留格式属性（粗体、斜体等），不会破坏文档结构。如果转为纯文本再转回来会丢失所有格式信息。

### 2. 跳过规则：基于节点属性判断
**选择**: 通过检查节点/行的属性来跳过特殊内容。
- 行内代码：Leaf 节点有 `inlineCode` 属性 → 跳过
- 代码块：Leaf 所在 Line 的父 Block 有 `code-block` 属性 → 跳过
- Embed 节点：非文本节点，遍历时自然跳过
**理由**: 利用 Quill 的文档模型天然区分内容类型，无需正则匹配。

### 3. 格式化算法：正则替换
**选择**: 使用正则 `([一-龥])([a-zA-Z0-9])` 和 `([a-zA-Z0-9])([一-龥])` 匹配中英文边界，插入空格。
**理由**: 正则简洁高效，Unicode 范围 `一-龥` 覆盖 CJK 统一汉字基本区。相邻已有空格时正则不匹配（因为空格不属于英文或中文字符集）。

### 4. 操作方式：compose 替换
**选择**: 收集所有需要替换的 (offset, oldText, newText) 对，然后用单个 Delta compose 一次性应用。
**理由**: 单次 compose 保证 undo 一次即可撤销整个格式化操作。

## Risks / Trade-offs

- [格式化误判] → 算法仅处理中文字符与半角英文/数字的边界，不处理标点、符号，影响范围可控
- [性能] → 对长文档需遍历所有节点，但文档通常在万字符级别，正则替换性能足够
